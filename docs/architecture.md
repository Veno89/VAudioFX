# Architecture and audio processing

`domain/model.ts` defines bounded, versioned projects, tracks, clips, effect values, and source metadata. `ProjectStore` owns state; React subscribes to its snapshots. History holds up to 80 complete immutable project snapshots. Original blobs are outside history, so undo cannot erase recordings.

`audio/assets.ts` owns format checks, sequential decode, an LRU-style decoded-buffer budget, browser errors, and optional pack caching. `audio/preflight.ts` checks WAV container/chunk/sample layout and known OGG Vorbis/Opus channel, rate and granule declarations before native decoding, including declared PCM duration and memory bounds. Other supported codecs still rely on the native decoder before decoded-duration/channel/allocation validation; these checks do not establish complete codec security. Clips reference source IDs. `Waveform` derives peak bins from decoded channel data in the selected original region. Nothing generates decorative random waveforms.

`audio/recorder.ts` owns microphone streams, MediaRecorder, its monitoring graph, elapsed time, and cleanup. Monitoring is disabled by default and uses a quiet gain. Track end and encoder failure stop capture. Recording limits are 120 seconds or 30 MB. Pending permission streams arriving after cancellation are stopped. Leaving the tab stops capture; unmount/page close releases tracks. Failed storage offers a downloadable original take.

`audio/cleanup.ts` processes owned copies of selected source regions before reversal and playback-rate changes. The gate uses a 2 ms energy detector, linked stereo gain, threshold hysteresis, and smoothed attack/release. It suppresses noise between sounds, rather than claiming speech noise removal. Region normalization targets −1 dB with a 10× gain cap. Quiet-edge analysis scans either source channel above the chosen threshold, keeps 10 ms padding within the current trim, and edits only trim instructions. No original audio is rewritten.

`audio/graph.ts` defines prepared source → playback rate → gain/fades → gain automation → ordered effect chain → clip pan/automation → track gain → track pan → output. The chain contains high-pass, low-pass, three-band EQ (180 Hz low shelf, 1 kHz broad middle band, 4.5 kHz high shelf), saturation, native compression, deterministic convolution room reverb, and three-tap delay. Whole-chain and individual bypass preserve settings and bypass low-pass automation. Neutral EQ and bypassed compression are defaults. Native compression has a small lookahead delay (approximately 6 ms). Fades handle overlapping lengths. Gain automation uses a separate multiplier node, preserving its exact product with fades. Pan/filter ramps use native AudioParam scheduling.

Region preparation performs DC removal, electrical-hum filtering, gating and optional normalization, then reversal and independent pitch. The three Q=25 notch filters use the [RBJ biquad equations](https://www.w3.org/TR/audio-eq-cookbook/); processing in source time keeps their frequencies correct when pitch/rate change. `audio/pitch.ts` streams linked stereo blocks through [SoundTouchJS core 2.1.1](https://github.com/cutterbl/SoundTouchJS/tree/d9e39a7ddcf74c7a145bbba45856f30068c82b79), using WSOLA/Lanczos with 40 ms sequences, 10 ms search and 8 ms overlap. A bounded silence flush retains the selected region's frame count. Pitch is limited to one octave; it can soften transients and color voices. Playback rate remains a separate pitch-and-speed control. Identical source/trim/reverse/cleanup/pitch regions share prepared buffers; unique regions have a separate 150 MB budget.

`audio/render.ts` creates an OfflineAudioContext using the export sample rate/channel count and shared graph. It permits one render at a time. Only audible source IDs are decoded, while duration includes muted-track timing. `audio/audio.worker.ts` prepares owned region copies, validates finite output, applies optional peak normalization to −1 dB (10× cap), then optional explicit hard peak limiting at −1 dB. The limiter reports affected samples and can add distortion. `audio/work.ts` transfers owned copies to a task-owned worker and terminates it on success, error, abort or a two-minute deadline. Sources and the preview buffer are never transferred/detached. Allocation reporting counts composition source/prepared/mix buffers, not total process memory or worker/browser overhead. Room impulse length is 1.5s; combined room/echo tails need 2.2s.

Abort signals terminate workers and prevent subsequent DSP stages/downloads. Native OfflineAudioContext has no close/cancel API: abort stops/disconnects nodes and retains the single-render lock until the bounded native job finishes. Requests during that interval receive an explicit finishing message. Editing, stopping, closing export and page hiding invalidate pending work. Render caching depends on tracks and mix settings; filename, zoom, audition loop and codec changes do not need another mix.

Compressed source metadata and native decoders can disagree about priming or padding. Rendering preserves the declared clip endpoint while region preparation clamps to decoded frames. Trims beyond both endpoints, or entirely beyond decoded audio, receive an explicit error; original samples remain unchanged.

Preview renders this buffer and plays it through `PlaybackEngine`, which uses the AudioContext clock for the playhead. Audition loops use the source node's native loop boundaries and modulo audio-clock position; pause retains the wrapped position. Loop ranges must fit the rendered audio and last at least 50 ms. WAV encodes the full buffer, regardless of audition settings. Editing stops playback; playing again renders the updated project. Preview gain is an independent listening control (35% default) and is not exported. Rapid play/stop actions invalidate pending work and keep one active source. The UI reports real decoding/rendering activity without invented percentage progress.

Playhead frames schedule a cancellable task to publish the latest audio-clock position to React. Frame callbacks do not update React directly, avoiding the observed Firefox page-close reentrancy warning. Page hiding cancels both handles, pauses playback, and invalidates pending preview/cleanup work; a restored page resumes in a stopped, usable state. Source-context disposal detaches the closing context before awaiting it, so a new decode retains ownership of its new context.

`storage/database.ts` uses IndexedDB transactions for project/source/active-project saves. A failed or canceled transaction cannot overwrite the previous successful save. Closed/version-changed connections clear the cached connection promise, so subsequent operations reopen safely. Autosave debounces changes by 750ms; explicit saves are serialized. Originals are saved before they become available in the library. `export/project-package.ts` owns a module worker for packaging/import, backed by `package-core.ts`; each task terminates on completion/error/abort or a two-minute deadline. Import validates stored ZIP directories, payload CRC and SHA, project contracts and bounded source metadata before native decoding and atomic saving, and remaps project/source IDs to protect existing library entries. Closing the project dialog or leaving the page cancels pending package work.

`storage/presets.ts` stores up to 128 validated effect chains in the existing settings store. Presets contain order, bypass flags, and effect parameters; they do not capture audio, clip timing, rate, or cleanup. UI save/delete state changes only after persistence completes, so quota failure preserves the last saved collection. Project schema migration is independent from the unchanged IndexedDB database version.

`audio/synthesis.ts` generates bounded mono 48 kHz original WAV sources. Native offline oscillators supply band-limited sine/square/sawtooth tones and exponential sweeps; white noise uses a seeded integer generator, and approximate pink noise uses an original twelve-row octave-rate Voss-McCartney implementation with a white component each sample. Sources have soft edges, hit/swell/steady envelopes, optional amplitude pulsing, finite sample checks, and a maximum 0.45 sample magnitude. Duration is 50 ms–10 seconds, tonal frequencies are 20 Hz–10 kHz, and variation is a 32-bit integer. Noise is deterministic; native oscillator output can vary slightly by browser. No external DSP dependency or copied third-party code was added. See the [native oscillator contract](https://www.w3.org/TR/webaudio-1.0/#OscillatorNode) and [Voss-McCartney algorithm discussion](https://www.firstpr.com.au/dsp/pink-noise/).

`features/templates.ts` assembles twelve complete, locally generated compositions. Footsteps reuse two original sources across eight independently editable clips. Creature and whisper descriptions identify synthesized textures rather than claiming a human voice. Template originals and the new project are persisted atomically without activating the prepared project; loading it triggers the normal autosave. Failed or canceled preparation leaves the current project active.

`features/creative.ts` maps built-in characters and four macros to ordinary clip rate/gain/effect instructions. Macros enable the processors they use and retain effect order. Size changes playback rate and therefore duration; the interface states this explicitly. All edits use ProjectStore history and the shared render/export graph. Custom chains continue to use the existing validated local preset store.

`features/recipes.ts` and `RecipeGuide` provide three interactive guides with concrete editor actions. The Undead guide requires a selected imported/recorded voice, adds a quiet synthesized texture on a separate layer, and sets an explicit 2.2-second tail. Guides retain the target clip ID across selection changes, reject removed targets, and advance only after successful actions. Recipe progress is session UI state; applied edits and originals persist normally. Generation is guarded against duplicate requests, stops preview, and checks operation/project identity before insertion. Originals enter the library only after successful persistence; closing a pending generator invalidates its timeline insertion.

Native compressor behavior, including fixed lookahead, follows the [Web Audio specification](https://www.w3.org/TR/webaudio-1.0/#DynamicsCompressorNode). Browser implementation details can affect the exact compression response.

`export/audio.ts` encodes copies of the preview mix in a worker. WAV is PCM16; [wasm-media-encoders 0.7.0](https://github.com/arseneyr/wasm-media-encoders/tree/4a45333baadbab312d1cc0911151dfad23157c51) supplies Ogg Vorbis quality 5 and LAME MP3 at 192 kbps. WASM is bundled as separate local files; there is no CDN or end-user encoder installation. Encoded chunks are copied before memory reuse. Browser/encoder priming can change lossy playback length; WAV remains the exact-timing recommendation.

The production offline shell precaches hashed app/worker/codec assets and provides a navigation fallback. Originals stay in IndexedDB; sample-pack caching remains explicit. Only listed same-origin static assets use this cache. Matching ignores Vary headers for known files, avoiding Chromium/Vite Origin-header misses. New versions activate after old clients close and delete only VAudioFX shell caches. Storage restrictions can prevent installation.

Limits: 16 tracks, 128 clips, 120s content, 32 points per automation lane, 30 MB originals, and separate 150 MB source/prepared-worker budgets. Decoding is serialized. Preparation/mastering/encoding and native DSP stay off the UI computation path; buffer copies remain bounded. Portable ZIP packaging is still synchronous and merits larger-package qualification in Milestone 5. Help reports browser storage estimates and the latest composition allocations. A 60-second stereo render checks sharing and event-loop responsiveness; sustained peak-memory profiling remains separate qualification.

Runtime dependencies are React/React DOM, Lucide, fflate, SoundTouchJS core and wasm-media-encoders. Native Web Audio supplies scheduling and the effect graph; a waveform framework is unnecessary. [Audio dependency notices and corresponding source](../public/third-party/index.html) are shipped with pinned revision/size/SHA-256 checks. System fonts avoid remote requests. There are no runtime analytics, audio uploads or external service calls. Publisher/license links open only when clicked.
