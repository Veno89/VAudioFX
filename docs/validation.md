Portable processing now runs in a bounded, cancelable module worker. Regression coverage checks truncated ZIP prefixes, local/central/end-directory agreement, unsupported flags, paths, CRC/SHA, UTF-8, manifest bounds and inert imported URLs. Original license/author/tags/generation verification survive repeated backups. A disposable browser-storage deletion workflow restores byte-identical originals and advanced settings without external requests. Forced IndexedDB close/reopen and canceled partial saves preserve the previous project and active-project pointer.

Boundary fixtures reproduced and corrected two package inconsistencies: the importer previously spent the audio budget on manifest bytes, rejecting a backup at the exporter's audio limit; the exporter could emit a manifest larger than the importer accepted. Scaled-budget tests exercise exact-limit roundtrips, excess-audio rejection in both directions and oversized-export-manifest rejection without allocating 150 MiB in unit tests. Audio, manifest and whole-archive budgets now agree.

WAV sample layout and known Vorbis/Opus duration/channel/allocation declarations are checked before native decoding. Other supported codecs still depend on native decoding before decoded bounds; this is not complete codec-security or fuzz qualification. Production checks compare the actual security headers, install the offline shell, disconnect/reload, generate/pitch and download MP3, OGG and a portable backup with no console errors or uncaught exceptions. All bundled worker/codec files are in the precache.

The synthetic maximum workload renders 120 seconds, 16 tracks and 128 clips with a shared pitched region, then exports/imports a 23,139,547-byte backup with unchanged original bytes and successful cancellation. Exact source/prepared/mix buffers total 97,920,000 bytes (93.38 MiB). The final gate measured render times of 7,980 ms / 2,890 ms and largest timer gaps of 127 ms / 121 ms in Chromium/Firefox. A separate Windows profiling run measured owned browser-process baselines and sampled peaks; see [release qualification](release.md) for figures, scenario and limitations. It does not qualify every source/effect combination or lower-memory hardware.

Automated accessibility found insufficient secondary-text contrast and missing modal focus restoration; both were corrected. Native button activation and clip Space selection now retain their keyboard semantics. Automated scans cover the empty editor, generator, selected/expanded inspector, export/project/idle-recording/help/license dialogs and template library. They do not establish full WCAG conformance or replace screen-reader review.

One earlier gate was deliberately interrupted to correct the QA runner's profiler-error exit status. Its tracked browser tree required force after graceful termination was refused; all owned processes exited, and the existing dev server was preserved. The final complete gate passed after that correction and the subsequent package-boundary fix, without weakening checks or adding retries. Earlier production-test integration mistakes involving JSON import attributes and automatic export-dialog closure were corrected before the final pass. Logs and screenshots remain in ignored `.qa/`.

All five implementation milestones are present. **Milestone 5 manual signoff remains open** for real microphone/monitoring hardware, installed Edge, human listening, assistive technology, actual browser-driven eviction, lower-memory devices and broader native-codec robustness. The gate retains the previous milestones' import, recording, editing, storage, generator, recipe, template, portable-original, DSP and WAV workflows. Tests inspect real rendered and decoded samples; microphone automation uses fake devices. Console errors and uncaught exceptions fail workflow checks, and Vite-forwarded console errors also fail the runner.

Advanced audio checks verify independent pitch frequency, exact frame counts, stereo balance and unchanged originals; gain/pan/low-pass automation; split interpolation and full-lane point limits; DC removal and 50/60 Hz hum/harmonic attenuation with retained signal. Version 1 and 2 projects migrate to version 3 with neutral advanced defaults. Advanced edits survive undo/redo, local reload and portable recovery. Source navigation supports zoom, precise seeking and keyboard movement. The project output summary follows the chosen codec.

Codec checks encode WAV, Ogg Vorbis and MP3 at 44.1/48 kHz in mono/stereo: twelve combinations per browser. They verify actual headers, MIME, native decoding, channel balance, exact WAV byte equivalence and Vorbis final granule frame counts. Lossy decoder priming is measured separately from encoded frame counts. Canceling worker encoding permits retry without detaching originals or the preview mix. The production workflow installs the built shell, disconnects the browser, reloads, generates and independently pitches a source, then downloads MP3 without page errors.

A 60-second stereo composition containing two shared 30-second pitched regions reported 11,520,000 decoded bytes, 11,520,000 prepared bytes and 23,040,000 rendered bytes: **46,080,000 bytes (43.95 MiB)** of composition buffers. The final run took 3,260 ms in Chromium and 2,974 ms in Firefox; the largest UI timer gaps were 109 ms and 92 ms respectively. These are local measurements, not whole-browser peak-memory figures. Worker copies, native DSP allocations and other browser overhead are excluded. Sustained peak-memory and maximum-project qualification remain in Milestone 5.

Validation found and corrected a trim regression: Chromium decodes the first bundled footstep to 0.143667 s versus its declared 0.144785 s; Firefox decodes it to 0.144792 s. Rendering now respects the declared timeline endpoint and clamps prepared regions to available frames. A regression checks normal, reversed and independently pitched renders, original preservation, and rejection of unavailable trims. The offline cache was corrected to ignore Vary headers when matching known static files. Codec tests check exact encoded Vorbis frames while separately allowing measured native decoder priming; audio quality assertions were not weakened.

An earlier generator failure coincided with an unsolicited Vite reload while the task's temporary source-download directory was removed. Subsequent focused and full workflows passed after cleanup. Firefox also intermittently failed browser-context teardown with a `Browser.removeBrowserContext` / `_maybeDontRestoreTabs` protocol error after application assertions completed. The focused offline retry and the final complete gate passed without suppressing the error, changing assertions or adding automatic retries. This harness instability remains documented; the final pass does not establish its root cause or eliminate the flake. Strict types in the new regression test were corrected before the passing gate.

Native OfflineAudioContext has no close/cancel API. Cancellation stops and disconnects its graph and prevents subsequent processing/downloads, while the single-render lock remains until that bounded native operation finishes. Pitch can soften transients or color voices. The limiter remains an explicit hard peak clipper with an affected-sample count; gate/DC/hum cleanup is not advertised as speech denoising. Originals stay local and unchanged, and WAV remains the recommendation for exact playback timing.

Real microphone/monitoring hardware, installed Edge, human listening, assistive technology, deeper storage eviction/recovery, import-security review, larger portable-package responsiveness, whole-process peak-memory stress and production release qualification remain unverified Milestone 5 work. The production offline shell needs an initial online visit and browser service-worker/storage support; library packs need explicit caching. Development mode uses the dev server. Dependency source archives and full notices are distributed with the application.
